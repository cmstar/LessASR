# 就地听写与独立听写设计

日期：2026-08-18

## 目标

LessASR 统一提供两种都支持连续分段的听写方式，并按结果最终去向命名：

- **就地听写**：按右 Alt 开始，完成后将整次听写一次性写入开始时捕获的光标位置。
- **独立听写**：按 F9 打开专用窗口，在窗口内连续听写、编辑和复制，不向外部光标位置写入。

本规格取代“右 Ctrl 单句听写 / F9 连续听写”的产品定义。内部已有的 `ContinuousDictation*` 类型可以继续作为技术名称；用户界面与现行文档统一使用“就地听写 / 独立听写”。

## 设计原则

- 连续说话不应等待上一段识别完成。右 Ctrl 提交当前段后立即开始下一段录音。
- ASR 请求保持 FIFO 串行消费；“不阻塞”指录音不等待识别，不要求并发调用多个识别服务。
- 识别结果始终按录音顺序展示和合并，不能因完成时间不同而乱序。
- 就地听写只在最终确认时写入外部输入框；分段过程中不提前注入。
- 两种听写互斥，避免争抢麦克风、热键路由、浮窗和识别服务。

## 名称与入口

| 功能 | 入口 | 简短说明 |
| --- | --- | --- |
| 就地听写 | 右 Alt | 完成后写入当前光标位置 |
| 独立听写 | F9 | 在独立窗口中连续听写和编辑 |
| 下一句 | 右 Ctrl | 仅在任一模式正在录音时提交当前段并立即录下一段 |

左 Alt 与左 Ctrl 不参与。右 Alt 是 LessASR 专用键：首次 `KeyDown` 立即执行，按下、系统重复和松开消息全部由 LessASR 拦截，按住不重复触发；因此 LessASR 运行期间右 Alt 组合键与 AltGr 不可用。成对拦截保证前台应用不会只收到按下或松开的一侧。右 Ctrl 和 F9 仍只在一次未参与组合键的完整按下并释放后执行并保持原始事件透传；空闲状态下右 Ctrl 不执行 LessASR 操作，也不得被吞掉。

## 就地听写

### 开始与目标捕获

1. 用户按下右 Alt；LessASR 在首次 `KeyDown` 立即触发，并拦截本次右 Alt 的全部按键消息。
2. LessASR 在触发时捕获当前前台窗口、可编辑控件和光标位置，沿用既有单句听写的目标捕获与注入策略。
3. 应用取得听写活动租约，显示现有紧凑浮窗并开始第一段录音。
4. 本次会话后续的焦点切换不改变已经捕获的目标。若开始时没有可编辑目标，仍允许听写，最终进入复制结果态。

### 单段路径

如果用户没有按过右 Ctrl：

1. 第一次右 Alt 开始录音。
2. 第二次右 Alt 提交当前有效录音并停止继续录制。
3. 识别完成后向开始时捕获的目标写入文本。
4. 目标不存在、已经失效或注入失败时，浮窗展示合并结果和“复制文本”按钮。

这一条路径保留原来单句听写的紧凑体验，但产品名称统一为“就地听写”。

### 连续分段路径

录音过程中按右 Ctrl：

1. 停止当前段录音。
2. 有效段在列表中的固定位置变为 `Transcribing`，进入 FIFO 识别队列。
3. 不等待识别结果，立即启动下一段录音并在列表底部建立新的 `WaitingInput`。
4. 上一段完成后在原位置更新为 `Completed` 文本或 `Failed` 占位。
5. 此时不向外部目标写入任何内容。

用户可以重复按右 Ctrl。识别队列最大深度为 **50 段**；达到上限后停止继续录音并提示用户，已经提交的段继续处理。

### 最终提交

录音过程中再次按右 Alt：

1. 当前有效段进入识别队列，不再开始下一段；不足 0.3 秒的无效段直接移除。
2. 浮窗进入“正在完成识别…”状态，等待所有已提交段落按 FIFO 完成。
3. 按列表顺序取全部非空 `Completed` 文本，以换行符（`\n`）合并；`Failed`、`WaitingInput` 与 `Transcribing` 不进入正文，也不产生空行。
4. 将合并正文作为一次操作写入开始时捕获的目标。
5. 若目标不可用或注入失败，切换为复制结果态，不丢失已完成正文。
6. 非空正文按一次就地听写会话保存为**一条**历史记录；直接注入与复制回退使用同一正文。

若所有段都无效或失败，不执行空文本注入，也不写空历史；浮窗保留失败占位或提示没有可提交内容。

## 就地听写浮窗

### 初始紧凑态

第一次按右 Alt 后继续使用现有约 118 px 宽的录音浮窗：

```text
[停止录音]  [实时波形]  [完成听写]
```

浮窗不激活、不抢走外部输入焦点。当前正在录制的段由波形行表示，不额外创建空白文本卡片。

### 第一次分段后的展开态

第一次按右 Ctrl 后，浮窗在原位置向上增长：

- 原来的录音行固定在底部，取消操作、实时波形和完成操作保持可见，视觉与动画不变。
- 已提交段落显示在录音行上方；最新段最靠近录音行，旧段依次向上移动。
- 段落区达到最大高度后内部滚动，底部录音行不滚走。
- 录音期间段落只读，浮窗继续保持不激活，避免改变最初捕获目标。
- 未按过右 Ctrl 时不展开，仍是原有小浮窗。

段落状态：

| 状态 | 展示 | 是否进入最终正文 |
| --- | --- | --- |
| `WaitingInput` | 由底部波形行表示当前录音 | 否 |
| `Transcribing` | “识别中…”与进度反馈 | 否，等待完成 |
| `Completed` | 识别文本 | 是 |
| `Failed` | “识别失败”及可选简短错误摘要 | 否 |

失败项使用弱错误色，保留在原顺序位置，仅作为界面提示；不得写入、复制或保存到历史正文。统计仍按每段识别尝试记录成功或失败。

### 审阅与复制态

停止继续录音后，浮窗可以进入审阅态：

- 已完成文本允许编辑；最终写入、复制和历史使用编辑后的内容。
- 仍在识别的段继续在原位置更新；失败段保持只读占位。
- 无可用输入目标或注入失败时，使用现有复制结果布局展示合并文本和“复制文本”按钮。

## Esc 与关闭操作

就地听写采用两阶段取消：

1. **录音中第一次按 Esc，或第一次点击关闭按钮**：停止并丢弃当前尚未通过右 Ctrl 提交的录音；已提交段继续完成识别；不注入、不写历史；浮窗保留并进入可编辑审阅态。
2. **审阅态再次按 Esc，或再次关闭浮窗**：丢弃本次会话的全部内容；不注入、不写历史。已经写入的分段统计不回滚。

审阅态按右 Alt表示确认：等待剩余识别完成后，将编辑后的成功段一次性写入原捕获目标。最终提交后的等待阶段，在真正开始注入前仍允许 Esc 取消；进入实际注入后不再接受取消。

## 独立听写

独立听写保留原 F9 专用窗口行为，仅调整产品名称，并与就地听写共享一致的分段语义：

- F9 在窗口不存在时创建、聚焦并置顶独立听写窗口，开始第一段录音。
- 窗口已经打开且未录制时，F9 追加一轮录制，不清空已有内容。
- 正在录制时按 F9，结束当前录制状态；当前有效段进入队列，不创建下一段。
- 正在录制时按右 Ctrl，提交当前段并立即录制下一段。
- 识别结果写入独立窗口的可编辑段落，不向外部目标注入。
- `Failed` 段显示与就地听写一致的失败占位，不参与复制或历史正文。
- 关闭窗口时，按既有规则合并成功段并写一条历史；“终止”清空会话且不写历史。

## 模式互斥与热键路由

| 当前场景 | 右 Alt | 右 Ctrl | F9 |
| --- | --- | --- | --- |
| 空闲 | 开始就地听写 | 传给前台应用 | 打开独立听写 |
| 就地听写正在录音 | 最终提交并停止继续录音 | 提交当前段并立即录下一段 | 忽略 |
| 就地听写审阅或正在完成 | 确认提交（适用时） | 忽略 | 忽略 |
| 独立听写窗口打开 | 忽略 | 录音时作为下一句边界 | 保持独立听写既有开关行为 |

任一模式从开始录音到不再录音且识别队列排空期间持有共享 `AsrActivityGate` 租约。期间禁止切换、编辑、删除、启停或重启识别服务，确保整次会话使用稳定路由；各段仍保存请求执行时的实际服务与模型来源。

## 历史、统计与来源

- 就地听写从右 Alt 开始到最终提交只产生一条非空文本历史，不按段拆分。
- 独立听写关闭窗口时仍只产生一条非空文本历史。
- 成功历史正文只由用户最终确认的 `Completed` 段按顺序合并而成。
- 每个进入识别流程的段分别写一次统计；失败段计入失败统计，取消和无效短段不计入识别统计。
- 多段来源一致时历史保存该服务与模型；混用来源时保存“多个服务 / mixed”。
- 取消会话不回滚已经写入的使用统计。

## 验收标准

1. 首页与帮助信息只使用“就地听写 / 独立听写”名称，并显示右 Alt、右 Ctrl 与 F9 的正确职责。
2. 右 Alt 能开始就地听写并捕获目标；未按 Ctrl 时保持紧凑单段体验。
3. 就地听写录音中按右 Ctrl 后，当前段进入识别，下一段立即开始，浮窗向上展开且底部波形行保持不变。
4. 上一段识别期间可以继续录制下一段；最终顺序与录制顺序一致。
5. 最后按右 Alt 后只发生一次合并注入，并只写一条历史。
6. 捕获目标缺失或失效时显示完整可复制正文，不丢文本。
7. 失败段在两种模式中都有可见占位，但不进入注入、复制或历史正文，也不产生多余换行。
8. 第一次 Esc 进入审阅，第二次 Esc 或再次关闭才彻底取消。
9. 空闲右 Ctrl 不被占用；两种模式严格互斥。
10. 队列上限、0.3 秒短段过滤、服务活动租约与来源快照保持有效。

# 连续听写模式设计

日期：2026-06-23

## 目标

在 LessASR 中新增**连续听写模式**：用户通过 F9 打开专用输入窗口，可连续说话、分段提交识别，在上一段仍在转写时即可开始说下一段，从而提高口述输入效率。识别结果写入窗口内的可编辑文本块；关闭窗口时将已成功识别的块合并为一条文本历史。

本规格聚焦连续听写的热键、会话状态、分段队列、专用窗口 UI、统计与历史规则。单句听写（右 Ctrl + 浮窗注入）行为不变，参见 [语音输入（听写）流程设计](./2026-06-09-dictation-flow-design.md)。

## 背景

- 现有 `DictationOrchestrator` 为单会话线性状态机：录音 → 转写 → 注入，无法并行「录下一段 + 识别上一段」。
- 现有 `IAudioRecorder` 同一时刻仅支持一路录音。
- 产品已定稿：单句默认热键为右 Ctrl；连续模式独立热键为 F9。

## 范围

### 包含

- F9 全局热键与连续听写专用窗口
- 分段录音、识别队列（最大深度 50）、列表项状态机
- 连续窗口开着时右 Ctrl 路由至连续模式（单句听写不可用）
- 每段识别完成时的统计写入；关窗时合并已成功段落写入文本历史
- Core 层 `ContinuousDictationSession` 与共享转写管线
- 单元测试与 `docs/domain.md` 更新

### 不包含

- 识别失败项的重试（单句与连续模式统一后续再做）
- LLM 后处理
- 连续模式文本注入到外部焦点控件（仅写入专用窗口）
- 多热键配置、用户自定义 F9 键位
- 队列内并行调用 whisper-server（仍串行消费，客户端排队即可）

## 架构方案

采用 **共享转写管线 + 独立连续会话**（方案 C）：

```text
LocalAsrClient.App
  ├── GlobalHotkeyListener（右 Ctrl）──┬─ 连续窗口未开 → DictationOrchestrator（现有）
  │                                    └─ 连续窗口已开 → ContinuousDictationCoordinator
  ├── GlobalHotkeyListener（F9）────────→ ContinuousDictationCoordinator
  └── ContinuousDictationWindow（WPF）

LocalAsrClient.Core
  ├── DictationOrchestrator（现有，单句）
  ├── ContinuousDictationSession（新增）
  │     ├── SegmentList
  │     ├── RecordingController（单路 IAudioRecorder）
  │     └── TranscriptionQueue（FIFO，max 50）
  └── TranscriptionPipeline（新增或抽取，ASR + 后处理，两模式共用）
```

**边界原则**

- Core 不依赖 WPF；会话状态与队列在 Core，窗口为 App 层 ViewModel 绑定。
- 连续模式**不使用**现有听写浮窗（`DictationOverlayWindow`）。
- 连续窗口存在期间，右 Ctrl 低级钩子仍吞键，但事件只发给连续会话。

## 热键

| 按键 | 单句模式（连续窗口未开） | 连续模式（连续窗口已开） |
| --- | --- | --- |
| **右 Ctrl** | 开始/结束单句听写（现有逻辑） | 句子边界：结束当前段并入队，新建「等待输入」，继续录音 |
| **F9** | 打开连续窗口并进入录制状态 | 见「F9 行为表」 |
| **Esc** | 取消当前单句录音（现有） | 结束录制状态；当前「等待输入」段不入队 |

### F9 行为

| 条件 | 按 F9 |
| --- | --- |
| 连续窗口不存在 | 创建窗口、聚焦、置顶，进入录制状态，列表追加首项「等待输入」并开始录音 |
| 窗口已开，未在录制 | 进入录制状态，列表末尾追加「等待输入」并开始录音（**不清空**已有项） |
| 窗口已开，正在录制 | 结束录制状态：当前段若有效则入队识别；**不**新建「等待输入」；队列中「识别中」项继续 |

F9 是**录制状态的开关**；窗口可长期保持打开，内容跨多轮录制追加。

### 右 Ctrl 职能总结

1. **单句模式**：一次听写的开始与结束边界（toggle）。
2. **连续模式**：句子与句子之间的边界（分段，非结束整个连续会话）。

## 列表项状态机

每一项对应一段语音，在 UI 上呈现为一个可编辑文本块（见「窗口 UI」）。

| 状态 | 含义 | UI 表现 |
| --- | --- | --- |
| `WaitingInput` | 正在等待/录制本段 | Placeholder：「等待输入…」；实际录音进行中 |
| `Transcribing` | 已入队，ASR 处理中 | Placeholder：「识别中…」 |
| `Completed` | 识别成功 | 显示识别文本（可编辑）；Placeholder 消失 |
| `Failed` | 识别失败 | Placeholder 或样式提示「识别失败」+ 简短错误信息 |

### 转移

```text
WaitingInput
  ├─[右 Ctrl]─> Transcribing + 新建 WaitingInput（若仍在录制状态）
  ├─[F9 结束录制]─> Transcribing（有效段）或移除（无效段）；不新建 WaitingInput
  ├─[Esc / 「结束录制」]─> 移除（不入队）
  └─[提交时时长 < 0.3s]─> 移除（无效段，不占位）

Transcribing
  ├─成功─> Completed
  └─失败─> Failed（保留，不阻塞队列后续项）

队列深度达 50 ─> 自动结束录制状态 + 用户可见提示
```

短于 **0.3 秒**的段与单句模式一致，视为无效，对应列表项**直接移除**。

## 录制状态与队列

### 录制状态（Session Recording Active）

- **进入**：F9（开窗口或窗口内再次开始）、首次 F9 打开窗口。
- **退出**：F9（结束当前段并入队）、Esc、「结束录制」按钮、队列满 50 自动停止。
- **退出后**：窗口仍开；识别队列继续消费；用户可编辑已完成块、可再次 F9 追加录制。

### 识别队列

- FIFO，最大深度 **50**（待 ASR 的段数）。
- whisper-server 请求**串行**发送；新段入队不阻塞下一段录音。
- 每段音频在入队前缓存在内存（`RecordingResult.WavData`），直至该段识别结束或会话终止。

### 终止与关窗

| 操作 | 行为 |
| --- | --- |
| **「终止」** | 立即停止录音；清空列表与队列；取消进行中的 ASR；**不写**文本历史 |
| **关窗口 (X)** | 按「文本历史」规则合并当前所有 `Completed` 块（若有）并写入一条历史；随后销毁窗口并释放资源 |
| **Esc / 「结束录制」** | 仅结束录制状态；当前 `WaitingInput` 不入队；窗口与已有项保留 |

已按段写入的统计**不撤回**（终止或关窗均不回滚 `IStatsRepository`）。

## 统计与文本历史

### 统计（按段）

每完成一段识别（成功或失败），调用一次 `IStatsRepository.RecordAsync`：

- **成功**（`Completed`）：`Succeeded = true`，计入成功数；写入字符数、词数、录音/处理时长。
- **失败**（`Failed`）：`Succeeded = false`，计入失败数。

与单句听写共用同一统计模型；每一段等价于单句模式的一次听写尝试。

### 文本历史（关窗时一条）

关闭连续听写窗口时（非「终止」路径）：

1. 收集所有 `Completed` 块当前文本（含用户编辑）。
2. 按列表顺序用 **换行符（`\n`）** 拼接为一条正文。
3. 若拼接结果非空，写入 **一条** `TextHistoryEntry`。
4. **忽略**：`Transcribing`、`WaitingInput`、`Failed` 项；不等待队列排空。

「复制」按钮仅复制当前所有 `Completed` 块（换行拼接），不写历史；与关窗时的合并规则一致，但不包含非 Completed 项。

## 窗口 UI

### 布局（三段）

```text
┌─ 连续听写模式 (x/y) ─────────────────────┐
│  [段 1 文本框 - Completed，可编辑]         │
│  [段 2 文本框 - Transcribing，placeholder] │
│  [段 3 文本框 - Failed，placeholder/样式]  │
│  [段 4 文本框 - WaitingInput，placeholder] │
├─────────────────────────────────────────┤
│ [终止]  [结束录制]  [复制]                │
└─────────────────────────────────────────┘
```

- **顶栏**：`连续听写模式 (x/y)` — `x` = `Completed` 数量；`y` = 列表总项数（含 Waiting / Transcribing / Completed / Failed）。
- **中间**：纵向滚动的段列表；**每一项为一个 div 式容器，内嵌单个 TextBox**（非 GroupBox 标题+正文结构）。
- **底栏**：`终止`、`结束录制`（同 Esc）、`复制`（仅 Completed 块，换行拼接）。

### 窗口行为

- **首次 F9**：窗口创建、**聚焦**、**置顶**（`Topmost`）。
- 录制过程中用户切换至其他应用：**不**停止录音；窗口失焦仍接收段状态更新与文本回填。
- 文本更新通过 ViewModel 绑定，**不依赖** TextBox 焦点或可见光标。
- Placeholder 文案（等待输入 / 识别中 / 识别失败）**不是**控件 `Text` 的一部分，复制与历史合并时**不包含** placeholder。

### 样式要点

| 状态 | Placeholder / 样式 |
| --- | --- |
| WaitingInput | 「等待输入…」（可选录制动效） |
| Transcribing | 「识别中…」 |
| Failed | 「识别失败」+ 错误摘要；区别于 Completed 的边框/颜色 |
| Completed | 正常正文，可编辑 |

## 与单句模式的关系

| 场景 | 行为 |
| --- | --- |
| 连续窗口未开 | 右 Ctrl → 现有单句听写 + 浮窗 |
| 连续窗口已开 | 右 Ctrl → 仅连续分段；单句 orchestrator 不响应 |
| 连续窗口已开 | 不使用 `DictationOverlayWindow` |
| ASR 未就绪 | 首次 F9 可显示「模型加载中」，就绪后再开始首段录音 |

## 错误处理

- 单段 ASR 失败：该项 → `Failed`，提示错误；后续段继续。
- 队列满：结束录制状态，提示已达上限；用户可等待队列消化后再次 F9。
- 终止：取消进行中的转写任务（若可取消）；列表与队列清空。

## 测试要点

### Core

- F9 逻辑：开窗、追加录制、结束录制不入队 vs Ctrl 入队。
- Ctrl 分段：入队 + 新 WaitingInput + 录音不中断。
- 短段 < 0.3s 移除。
- 队列 FIFO、深度 50 上限与自动停录。
- 每段成功/失败各写一次统计。
- 关窗合并历史：仅 Completed、换行、含用户编辑。

### App

- 连续窗口开着时右 Ctrl 不分流到单句。
- Placeholder 不参与复制。
- 失焦后录音与 UI 更新正常。
- 终止不写历史；关窗写历史（有 Completed 时）。

## 验收标准

1. F9 打开窗口并自动开始首段；右 Ctrl 可连续分段，上一段识别中时可说下一段。
2. F9 再次按下结束录制状态，当前有效段入队；Esc / 「结束录制」丢弃当前 Waiting 段。
3. 识别完成块可编辑；复制仅含 Completed，换行拼接。
4. 失败项保留显示，不重试；统计按段增减。
5. 关窗后一条历史含所有 Completed 合并正文；终止清空且不写历史。
6. 连续窗口开着时单句听写不可用。
7. 列表项 Placeholder（等待输入 / 识别中 / 识别失败）不参与复制与历史合并。
